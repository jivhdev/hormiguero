# B-006 — Revisión automática en GitHub y antes de cada commit

## Objetivo

Que cada push a GitHub compile, pruebe y revise el repo, y que cada commit local se revise contra secretos.

## Contenido exacto

1. `.github/workflows/ci.yml`: flujo llamado `CI`, en `push` y `pull_request` a `main`, en `windows-latest`. Pasos: checkout (con `fetch-depth: 0`), `actions/setup-dotnet` usando `global-json-file: global.json`, `dotnet tool restore`, `dotnet build Hormiguero.slnx -c Release`, `dotnet test Hormiguero.slnx -c Release --no-build`, `dotnet csharpier check .`, `dotnet nuget-license -i Hormiguero.slnx -a .config/licencias-permitidas.json`, y `gitleaks/gitleaks-action@v2` con `GITHUB_TOKEN`. Usa las versiones mayores vigentes de cada acción.
2. `.githooks/pre-commit`: script de shell (`#!/bin/sh`) que corre `gitleaks git --pre-commit --staged --redact --no-banner` y corta el commit si encuentra algo. Si `gitleaks` no está instalado, avisa en español y deja pasar el commit.
3. `.gitignore`: **agrega** al final (sin borrar nada de lo que ya tiene) las entradas estándar de .NET que falten: `TestResults/`, `*.suo`, `*.cache`, `artifacts/`, `capturas-temp/`.

## Casos límite

- El `.gitignore` conserva todas sus líneas actuales (en especial `*.pdf` y `.env`).
- El hook no falla si gitleaks no existe.

## Criterio de término

- El YAML es válido.
- `sh .githooks/pre-commit` corre sin error en el repo actual.
- `git status --short` solo muestra los archivos permitidos.
