# X-5 — Barra de título ilegible en modo oscuro (Windows 10)

Javier: "el modo oscuro se ve raro: las palabras del título de la ventana no se alcanzan a ver; todo lo de adentro está bien, el problema son las letras de afuera". Windows 10 22H2 (19045).

Hoy `Tema.BarraDeTitulo` (`src/Hormiguero.Diseno/Tema.cs`) llama `DwmSetWindowAttribute(hwnd, 20, 1)` en `Loaded` (vía `PintarTodasLasVentanas`). La ventana ya está visible en ese momento: Windows marca la barra como oscura (el texto queda claro) pero no la redibuja, así que queda **texto claro sobre barra blanca**. Ya se probó `SetWindowPos(SWP_FRAMECHANGED)` después y **no** sirvió.

Arreglo esperado:
1. Aplicar el atributo **antes** de que la ventana se muestre: en `SourceInitialized` de cada ventana (WPF no tiene evento enrutado para eso; usa por ejemplo `EventManager.RegisterClassHandler(typeof(Window), FrameworkElement.LoadedEvent, …)` solo como respaldo y, para el caso principal, engancha `SourceInitialized` desde algo que corra al crear cada ventana, como un estilo implícito con `EventSetter` no sirve para eventos CLR: investiga la forma correcta, p. ej. `ComponentDispatcher`/`HwndSource` o `Window` creado vía `Application.Current.Activated`, y documenta la elegida).
2. En Windows 10 anteriores a 20H1 el atributo es **19** en vez de 20: intenta 20 y, si falla (HRESULT distinto de 0), 19.
3. Si la ventana ya estaba visible (cambio de tema en caliente), forzar el redibujo del marco: lo que funcione de verdad (p. ej. alternar `WindowStyle` o minimizar/restaurar no; prueba `RedrawWindow(hwnd, NULL, NULL, RDW_FRAME|RDW_INVALIDATE|RDW_UPDATENOW)` o enviar `WM_NCACTIVATE` falso y verdadero).
4. Comprobación real: escribe una prueba STA que abra una ventana en tema oscuro, la muestre y lea con `DwmGetWindowAttribute(…, 20)` que vale 1 **antes** del primer render (registrando el orden de eventos). Además deja en el reporte instrucciones para que Claude la verifique visualmente.
