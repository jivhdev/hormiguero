# B-6g2 — Pantalla de Archivero: datos propios de cada tipo de documento

B-6c dejó la lógica para que una configuración de Archivero tenga **datos propios** con nombre libre leídos de una zona del PDF (p. ej. "N° OC", "N° guía"), pero falta la pantalla (ver `bloques/B-6c.md`). D-70, D-71: amigable y nada fijo.

1. Donde hoy se marcan las zonas de `Emisor`, `Tipo`, `Fecha` y `NombreArchivo` al identificar/configurar un documento, agrega **"Agregar dato"**: el usuario escribe el nombre ("N° OC"), marca la zona en el PDF igual que las otras marcas, ve el valor leído de ejemplo y guarda. Puede renombrar, cambiar la zona o quitar un dato propio (quitar = desactivar, nunca borrar los valores ya publicados).
2. Al guardar documentos, esos datos se publican como ya lo hace B-6c (no dupliques lógica).
3. Lecciones obligatorias: eventos de XAML durante `InitializeComponent`; tema claro y oscuro; 1366×768; español neutro; configuración de pruebas con `HORMIGUERO_DATOS`/`ARCHIVERO_DATOS` sin tocar datos reales.
4. Abre Archivero una vez con datos de prueba en carpeta temporal y confirma que la ventana de identificar y la de configuración abren sin caerse.

Pruebas para la lógica nueva (agregar, renombrar, cambiar zona, desactivar, valor leído). `dotnet build` sin advertencias; `dotnet test` todo pasa; `dotnet csharpier check .` sin errores. Reporte al final.
