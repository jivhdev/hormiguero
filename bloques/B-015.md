# B-015 — Cambiar entre modo claro y oscuro

## Objetivo

Que cada app siga el modo de Windows o el que elija el usuario, cambiando sin reiniciarse (N-008 de `semillas/Nucleo/SPEC.md`; D-35).

## Contenido exacto

1. `Tema.cs`:
   - `enum ModoTema { Sistema, Claro, Oscuro }`.
   - `static bool WindowsEstaEnOscuro()`: lee `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme` (0 = oscuro); si no existe, claro.
   - `static Uri DiccionarioPara(ModoTema modo, bool sistemaOscuro)`: devuelve la `Uri` de `Temas/Claro.xaml` u `Temas/Oscuro.xaml` (función pura, para probarla).
   - `static void Aplicar(Application app, ModoTema modo)`: quita el diccionario de tema anterior de `app.Resources.MergedDictionaries` y agrega el nuevo. Si el modo es `Sistema`, se suscribe a `SystemEvents.UserPreferenceChanged` para volver a aplicar cuando Windows cambie (y se desuscribe al cambiar a otro modo).
2. `tests/Hormiguero.Diseno.Tests/`: proyecto xUnit `net10.0-windows` con referencia a `Hormiguero.Diseno`, agregado a `Hormiguero.slnx` en `/tests/`; paquetes sin versión.
3. `TemaTests.cs`: pruebas de `DiccionarioPara` (las 6 combinaciones) y una prueba que carga ambos diccionarios y verifica que tienen las mismas claves.

## Casos límite

- `Sistema` + Windows oscuro → Oscuro; `Sistema` + claro → Claro; `Claro`/`Oscuro` ignoran Windows.
- Aplicar dos veces seguidas no deja dos diccionarios de tema cargados.

## Criterio de término

- Pruebas: `Elige_el_diccionario_correcto` (`[Theory]` 6 casos), `Ambos_temas_tienen_las_mismas_claves`, `Aplicar_dos_veces_no_duplica`. Pasan (las que usan WPF corren en hilo STA).
- `dotnet build` sin advertencias; `dotnet csharpier check .` sin errores.
